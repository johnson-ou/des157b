Feasibility Report

the air we share

Features

  • Scroll-driven narrative with multiple chapters that reveal as the user scrolls down
  • Animated lines that fade and rise into view at a smooth pace
  • Counter-animated statistics that count up from zero as they enter the viewport
  • Horizontally-pinned scroll section where the page scrolls sideways to reveal five industry emission-source cards
  • Staggered grid of "what's at stake" items that animate in on scroll
  • Three.js 3D forest scene, a GLTF model the user can orbit and zoom
  • Click-to-place wish mechanic using raycasting to detect where the user clicks in 3D space and opens a write-a-wish form
  • Communal wish storage via Back4App — wishes can be seen across sessions and are visible to all visitors
  • Glowing wish dots projected from 3D positions onto the screen, with a hover tooltip that shows the wish text
  • Ambient floating particle canvas behind all content, with color that shifts from warm to cool as the user scrolls
  • Click-and-hold up/down arrow buttons to scroll past the 3D section without triggering the camera zoom
  • Top fade gradient on the forest scene so zoomed-in treetops dissolve rather than clip

Technologies Required

  • HTML / CSS / JavaScript: base layer for all structure, styling, and behavior
  • GSAP + ScrollTrigger: fires and scrubs animations as the user scrolls; also handles the horizontal pin section, stat counter, and the reset-view camera
  • Three.js: 3D renderer, scene, camera, lights, fog, GLTFLoader for the forest model, OrbitControls for drag and zoom, and Raycaster for detecting wish placement clicks
  • Dynamic import(): loads Three.js modules inside the IIFE without needing a module-type script tag
  • HTML importmap — resolves the "three" and "three/addons/" specifiers
  • Back4App: cloud database for storing and retrieving wishes across all visitors
  • Canvas API + requestAnimationFrame: drives the ambient particle background; particles drift upward and the color change based on scroll depth

Skill Assessment

  • HTML + CSS: bulk of the project; comfortable, no concerns
  • Vanilla JavaScript: comfortable with what we covered in class; more advanced patterns like IIFE scoping, dynamic imports, and for...of loops were learned from MDN documentation
  • GSAP + ScrollTrigger: had no prior experience, but the documentation was thorough
  • Three.js: the steepest learning curve of the project; GLTFLoader, OrbitControls, raycasting, bounding-box math, and 3D-to-2D projection all required significant time reading the Three.js documentation and external tutorials
  • Back4App: relatively straightforward once the SDK was loaded correctly;
  • Canvas API: basic drawing methods were approachable; the devicePixelRatio scaling for sharp rendering on retina screens required a bit of extra research

Difficulties

  • Three.js learning curve: getting the GLTF model loaded, scaled to a reasonable size, and oriented so the camera faces the front of the house required inspecting the raw GLTF file's accessor data to find which direction the model was facing; this took much longer than expected
  • Scroll-zoom conflict: OrbitControls captures the scroll wheel for camera zooming, which made it difficult for users to scroll past the forest section normally; solved this by adding floating arrow buttons on the right side of the screen that only appear when the forest section is in view
  • 3D-to-2D wish projection: placing HTML wish dots at the correct screen position required calling camera.project() on each wish's Vector3 every render frame and converting the result from normalized device coordinates to pixel coordinates; this math was found in Three.js documentation and community examples
